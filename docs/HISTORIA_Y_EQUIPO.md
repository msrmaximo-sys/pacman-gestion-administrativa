# Historia colectiva y uso de IA

Este proyecto fue realizado por **cuatro compañeros**, con tareas compartidas y participación de igual valor. Por decisión del equipo, la documentación conserva la identidad colectiva: no incluye nombres ni atribuye módulos o tareas a una persona.

El uso de IA estuvo permitido. El objetivo académico incluye definir problemas, razonar soluciones y explicar el funcionamiento del programa. Hubo prototipos previos y el equipo considera esta la versión final. La copia revisada no incluía esos prototipos ni un historial Git.

## Contexto documentado

La propuesta fue diseñar un juego con Pygame e incorporar gestión administrativa, archivos, punteros lógicos, vectores y matrices. Los materiales aportados describen el método de lista enlazada y un modelo administrativo de palas y pelotas. La versión final los adapta a Pac-Man.

El código muestra el resultado técnico, pero no prueba en qué orden se implementaron los módulos ni qué problema apareció primero. Las fechas de modificación de archivos no sustituyen esa historia.

## Registro de decisiones para completar en equipo

Para cada cambio que recuerden, anotar juntos:

1. Qué comportamiento o requisito planteó el problema.
2. Qué alternativas discutieron o probaron.
3. Qué eligieron y por qué.
4. Qué función permite comprobar la solución.
5. Qué prueba hicieron y qué resultado obtuvieron.
6. Qué limitación aceptaron.

Temas útiles: paso de un prototipo al siguiente, control continuo y giros, uso de registros fijos, enlaces por usuario, identificación de objetos, matrices, momento de guardado y presentación de informes. Ninguno requiere identificar responsables individuales.

## Secuencia para explicar, no cronología inventada

Puede estudiarse en este orden: requisitos → contrato de datos → usuarios → tablero y personajes → movimientos y contactos → persistencia y cadenas → consultas → matrices → verificación. Es una organización didáctica; afirmar que fue el orden real solo si el equipo lo recuerda y confirma.

## Declaración colectiva

> Desarrollamos el proyecto entre cuatro compañeros, con autoría colectiva. Usamos asistencia de IA permitida y compartimos la responsabilidad de comprender el código, sus decisiones y sus límites. La documentación conecta la consigna con la implementación final para apoyar el estudio y la defensa oral.

Se pueden agregar herramientas utilizadas, ejemplos de propuestas corregidas y pruebas efectivamente realizadas cuando el grupo lo desee. No inventar revisiones, prompts ni resultados retrospectivos.

## Historial Git

El futuro primer commit conservará esta versión final y su documentación. No representará por sí mismo todas las etapas anteriores. No hace falta simular fechas ni repartir commits para sostener la participación igualitaria. El repositorio será privado y la creación y publicación quedan a cargo del usuario.
